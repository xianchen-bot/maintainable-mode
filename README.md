# maintainable-mode

一个面向日常软件开发的 Agent Skill：完整解决当前问题，优先保证代码的可读性与可维护性，减少不必要的实现和流程。

**把范围想清楚，把代码写清楚，用必要的验证证明结果。**

## 核心原则

1. **理解问题**：阅读相关代码，追踪数据流和调用方，确定完整影响范围，修复根因。
2. **完整实现**：优先复用项目已有能力，采用最简单的完整方案，保留必要注释，避免过度设计。
3. **按风险验证**：验证用户可观察的行为，为重要逻辑补测试，让简单改动保持轻量。
4. **清楚交付**：说明结果、关键改动和实际验证情况，遵循项目流程与已有授权。

完整执行规则见 [SKILL.md](SKILL.md)。

## 适用场景

| 场景 | 关注点 |
| --- | --- |
| 功能开发 | 复用现有组件和约定，完成必要调用链，不添加假想扩展点 |
| 缺陷修复 | 复现问题，补适当的回归验证，修复根因 |
| 代码重构 | 固定已有行为，改善结构，验证预期外行为没有变化 |
| 代码审查 | 结合相关上下文定位实际问题，说明触发条件和后果 |
| 遗留代码维护 | 尊重既有结构，小步改进，控制改动范围 |

纯概念问答和单纯文档写作不需要启用这套流程。

## 设计取舍

- **可维护性优先**：不以最少行数、固定函数长度或某个分数定义好代码。
- **必要注释不能省**：解释业务规则、设计原因、边界和取舍，避免重复代码表面含义。
- **复用需要业务语义一致**：结构相似可以提示问题，不意味着必须合并。
- **验证强度与风险匹配**：核心逻辑需要针对性测试，简单改动不承担整套高成本流程。
- **优先使用已有工具**：不强制依赖 Crapper、Dryer、Mutator 或其他额外工具链。

这是一个以文字指令为主的 Skill。它指导代理的工作方式；需要强制执行的质量规则，应接入项目自己的脚本或 CI。

## 文件结构

```text
maintainable-mode/
├── README.md
└── SKILL.md
```

`SKILL.md` 包含元数据和完整规则，可单独复制使用，无需额外脚本或 MCP 服务。IDEA MCP 是可用时的工具偏好，不是运行依赖。

## 安装与使用

### Codex

按 [OpenAI 官方 Skills 文档](https://learn.chatgpt.com/docs/build-skills)，个人技能可放在 `~/.agents/skills/`，项目技能可放在项目的 `.agents/skills/`。

在本仓库根目录运行以下命令，安装为个人技能。目标目录已存在时，先比较现有内容，再决定更新方式：

```sh
mkdir -p "$HOME/.agents/skills/maintainable-mode"
cp -i SKILL.md "$HOME/.agents/skills/maintainable-mode/SKILL.md"
```

然后在 Codex CLI 或 IDE 扩展中显式引用：

```text
$maintainable-mode 修复这个问题，重点检查调用方和回归测试。
```

也可以使用 `/skills` 选择该技能。Codex 支持按描述自动匹配技能；显式引用更容易确认当前任务采用了这套规则。若安装后未出现，可重启 Codex 再检查。

### 其他支持 Agent Skills 的代理

将 `SKILL.md` 放入宿主支持的技能目录，保持文件夹名称为 `maintainable-mode`，再使用宿主提供的技能选择或调用方式。

不同宿主的目录、自动发现机制和调用语法可能不同，安装位置与启用方式以对应宿主文档为准。

### 作为全局或项目提示词

如果宿主只支持自定义指令，可复制 [SKILL.md](SKILL.md) 中 YAML 元数据之后的正文，放入全局提示词或项目规则文件。

Skill 由宿主发现并选择加载；全局提示词则按宿主的指令加载机制生效。根据希望覆盖的范围选择一种配置方式，避免重复维护同一份规则。

## 工具与质量指标

优先使用项目已有的 IDE 检查、测试、覆盖率和静态分析工具。IDEA MCP 可用且适合当前操作时，优先用于符号分析、引用查找、重构和检查。

复杂度、结构相似度、覆盖率和变异测试用于发现候选问题，最终判断仍取决于业务语义、行为正确性和维护成本。对于已有大量技术债的项目，先关注当前改动涉及的范围，再安排独立治理任务。

本仓库提供工作规则，不声明缺陷率、成本或速度的量化改善。可以用自己的真实任务评估审查难度、回归情况、验证成本和后续修改成本。

## 灵感来源

- [DietrichGebert/ponytail](https://github.com/DietrichGebert/ponytail)：优先复用，减少过度实现和无用代码。
- [unclebob/ub-mode](https://github.com/unclebob/ub-mode)：根因修复、行为测试、小步验证和工程纪律。

本技能结合这些思路，以可读性、可维护性、必要注释和与风险相称的验证为主要取舍标准。
